# 任务清单

## Task 1：建立项目分发基线

### 目标

把当前库从“仓库内可编译”提升为“外部项目可标准接入”。

### 影响范围

- 根 `CMakeLists.txt`
- `components/CMakeLists.txt`
- 安装导出脚本
- 包配置模板

### 实施思路

- 统一库 target 命名与命名空间
- 补齐 `install/export/package config`
- 改造 include 导出为 `BUILD_INTERFACE` / `INSTALL_INTERFACE`
- 清理对构建目录产物路径的直接依赖

### 验证方法

- 新建最小外部 `CMake` 示例工程
- 通过 `find_package` 链接公开 target
- 验证无需手工指定库文件与头文件路径

## Task 2：重构示例程序消费方式

### 目标

让 `examples` 成为库的真实消费者，而不是构建耦合补丁。

### 影响范围

- `examples/CMakeLists.txt`
- 示例程序链接方式
- 示例运行时资源复制逻辑

### 实施思路

- 去除基于 `${CMAKE_BINARY_DIR}` 的平台产物路径拼接
- 改为直接链接公开 target
- 将运行时拷贝逻辑调整为 target 级依赖或安装后验证逻辑

### 验证方法

- 仓库内构建示例程序
- 验证示例仍可运行
- 验证示例未直接依赖构建目录中的 `components.lib/.so`

## Task 3：收敛公共 API

### 目标

消除公共头对私有实现的直接泄漏，形成稳定 API 面。

### 影响范围

- `include/qmetarial/**`
- `components/**`
- 私有头与内部头组织方式

### 实施思路

- 清点所有安装头文件
- 移除公共头中的私有 `_p.h` 依赖
- 对空壳、实验态、未完成组件建立导出分级
- 评估 `qmetarial` 命名迁移策略

### 验证方法

- 仅使用安装后的公共头进行独立编译
- 确认调用方不需要私有头即可完成编译
- 核对公开头与实现层目录依赖关系

## Task 4：拆分 Core / Widgets / Examples 边界

### 目标

明确主题样式能力、控件能力、示例能力的职责边界，降低耦合。

### 影响范围

- `components/materiallib`
- `components/`
- `examples/`
- 未来目录布局与 target 组织

### 实施思路

- 识别可归入基础能力层的模块
- 为 Core 与 Widgets 规划独立 target 或至少独立源文件分组
- 使 Examples 只依赖公开 API

### 验证方法

- 检查模块依赖图
- 确认基础层不反向依赖示例层
- 确认组件层仅通过基础层复用通用机制

## Task 5：补齐测试与 CI 基线

### 目标

建立基础库最小可信交付闭环。

### 影响范围

- 测试目录
- CI 工作流
- 构建矩阵

### 实施思路

- 引入 `QTest` 最小测试集
- 先覆盖关键公共组件与主题/资源初始化
- 建立 `Windows/Linux + Qt5/Qt6` 的基础构建校验

### 验证方法

- 本地执行最小测试集
- CI 成功构建主路径
- 至少一条接入验证链路通过

## Task 6：校准文档与发布说明

### 目标

让 README、API 文档、组件状态说明与实际代码保持一致。

### 影响范围

- `README.md`
- `Docs/API.md`
- 发布说明

### 实施思路

- 重新梳理稳定组件、实验组件、未实现组件
- 给出标准接入示例
- 明确主支持构建系统与兼容策略

### 验证方法

- 人工核对 README 与代码目录
- 按 README 示例完成一次外部接入
- 确认文档不再使用过时接入方式作为主路径
